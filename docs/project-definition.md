# 项目定义

## 1. 项目背景
`eva-agent` 用于设计和验证一个以生命循环为起点的自主生存 / 自我成长 agent。

这个项目不以“为用户完成任务”作为第一原则，而以“先维持本体存在，再在存在中成长”为核心目标。项目要验证的是：一个 agent 能否在真实运行、真实反馈与真实压力中，逐步形成自己的经验、技能和判断偏好，而不是一开始被设计成一个功能齐全的系统。

## 2. 设计哲学
### 2.1 生命循环先于生命函数
在定义生命函数之前，必须先有一个可持续存在的生命循环。没有稳定循环，就没有可评估的生命体征，更谈不上成长。

### 2.2 成长出来，而不是一次性设计出来
项目不追求先设计出一个功能强大且完备的 agent。更重要的是：先设计成长条件，让能力在后续运行中逐步长出。

### 2.3 从生命函数向外生长，而不是从现成 agent 框架向内裁剪
现有 agent 框架、loop、memory、skill、检索、蒸馏、微调等能力都可以作为参考或零件来源，但不应主导本项目的世界观。本项目的核心出发点是生命函数与生命循环，而不是“如何做一个更强的用户服务型 agent”。

## 3. 当前明确的核心概念
### 3.1 生命循环
一个由宿主环境守护、具备 heartbeat deadline、状态持久化、异常恢复和最小自监测能力的长期运行主循环。

### 3.2 外部生命函数
由设计者 / 宿主 / 守护系统视角定义，用于判断 eva 是否仍作为唯一、连续、可恢复的生命体存在。

### 3.3 内部生命函数
由当前运行中的 eva 本体视角定义，用于实时评估当前这一代本体的生命体征是否稳定、退化、危急或恢复中。

### 3.4 后续成长层（暂不进入实现）
后续成长大致分为三层：
- 记忆成长：积累经历并形成可检索的情景经验
- 技能成长：把成功模式沉淀为可复用 skill
- 判断偏好固化：通过更慢时间尺度的方式，把有效偏好逐步固化进本地模型或适配层

## 4. 当前阶段：Step 0
Step 0 的目标不是让 eva 有很多能力，而是让 eva 有清晰、稳定、可观测的生命体征。

当前 Step 0 的重点：
- 定义生命循环
- 定义外部生命函数与内部生命函数
- 定义 heartbeat / tick / turn 的边界
- 定义最小生命体征指标集
- 定义第一版宿主环境与最小运行壳
- 把上述定义落到可运行、可测试、可部署验证的最小 Python 运行壳

## 5. 当前非目标
在 Step 0 未固定前，暂不展开：
- 多工具系统
- 长链路任务能力
- 对外业务能力
- 复杂记忆体系实现
- skill 自动生成
- LoRA / 蒸馏工程落地
- 经济系统与独立生存策略

## 6. 当前已定的工程起点
### 6.1 宿主环境
第一版不考虑本地长期运行。为了支持长期运行测试，宿主环境优先选择：
- 云主机，或
- 其他可长期运行的 Linux 机器

环境假设优先采用：
- Ubuntu
- bash 运行环境

这样更符合长期存活、守护、自动恢复和后台运行的需求。

### 6.2 实现语言
第一版实现语言优先采用 Python。

原因：
- 便于快速搭最小运行壳
- 更适合实现长期运行 loop、状态持久化、守护配合和实验性结构
- 在 Step 0 阶段比先引入更重的工程形态更直接

## 7. 当前时间尺度分层
### 7.1 Step 0：基础生命脉搏
Step 0 的 heartbeat 只承担生命脉搏职责，不承担更高层巡逻任务。

当前默认建议值：
- 基础 heartbeat：15 秒
- 约 45 秒进入 `DEGRADED`（连续错过 3 次 heartbeat）
- 约 135 秒进入 `CRITICAL`（连续错过 9 次 heartbeat）

### 7.2 Step 1：巡逻与报告层
Step 1 再在基础 heartbeat 之上叠加更慢时间尺度的巡逻：
- shallow patrol：5 分钟
- deep patrol：30 分钟
- full report：24 小时

也就是说：
- Step 0 解决“ta 有没有持续活着”
- Step 1 解决“ta 有没有按层级完成生存巡逻和完整状态审视”

## 9. 当前已定的实例合法性思路
Step 0 不让本体自己直接判断“世界上是否存在另一个我”，而是通过一个内部可读的合法性投影信号 `instance_valid` 来判断：

- 我是否仍持有行动权
- 我是否仍是当前这一代
- 我的合法身份是否仍未过期

第一版最小机制采用：
- lock
- generation
- lease_expiry

其目标不是构建复杂分布式一致性，而是在单机长期在线环境中先保证：
- 同一时刻只有一个合法执行者
- 旧代实例能被识别为过期
- 本体一旦失去合法执行身份，就停止代表 eva 行动

## 10. 当前已定的最小运行壳边界
Step 0 的最小运行壳已经收敛为：
- supervisor 配合层
- 单实例合法性层
- 事件驱动主循环层
- 基础 heartbeat 层
- turn 执行层
- 状态持久化层
- 最小 distress / yield 机制

并明确排除：
- LLM 调用
- 多工具系统
- 长链路任务编排
- 复杂记忆检索
- 多渠道网关
- 经济系统
- LoRA / 蒸馏
- 多机分布式一致性
