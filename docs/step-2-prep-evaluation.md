# Step 2 前阶段评估与方向调整

## 1. 文档目的
本文用于在进入 Step 2 之前，对 `eva-agent` 当前阶段的主线、阶段成果、理论修正点与下一步收敛重点做一次正式回顾。

它不承担实现规格职能，也不直接定义 Step 2 的模块设计。本文的作用是回答四个问题：

1. 项目当前是否仍在最初目标上推进
2. Step 0 与 Step 1 已经真正建立了什么
3. 哪些中间推导已被证明不够稳，需要调整
4. 在正式启动 Step 2 之前，还必须先把哪些问题收紧

## 2. 当前阶段状态
### 2.1 Step 0 已形成可复用 baseline
当前已经稳定建立：
- heartbeat-first 生命循环
- `tick / turn` 边界
- `instance_valid` 合法性投影
- 状态持久化与最小运行壳
- distress / yield 机制
- Linux user systemd 长时运行与异常路径验证

### 2.2 Step 1 核心结构已形成
当前已经完成：
- 外部生命感知
- 规则式生命判断
- 生存压力生成
- 最小生存历史
- patrol 调度与持久化结构

### 2.3 Step 1 形式收口仍依赖真实长时观察
Step 1 的实现、测试、accelerated 验证与异常注入验证已基本完成。形式上的最终收口，仍依赖真实 Linux 节律下的长期观察结果，尤其是：
- 服务在真实 cadence 下持续稳定运行
- 至少出现一次真实 `full` cadence / full report
- heartbeat-first 生命周期边界在长时窗口内仍保持成立

因此，Step 2 的理论准备可以先推进，但 Step 1 的长期观察结论仍应保留为正式收口条件之一。

---

## 3. 项目初心回顾
`eva-agent` 的起点不是构建一个更强、更方便、更会完成外部任务的 agent。

它的出发点是：
- 先构建一个可持续存在的运行体
- 再让这个运行体开始形成生命体征、外部生命感知、生存压力与可回顾历史
- 再在这个基础上讨论技能、偏好、记忆与成长

因此，本项目最核心的问题并不是：
- 如何尽快把 LLM、tool use、memory、skill 叠加进去
- 如何尽快把 eva 变成高能力任务 agent

而是：

> 是否可能构建一个以自身连续存在为中心、而不是以外部任务完成为中心的 agent 个体。

这个初心决定了：
- 生命循环优先于功能堆叠
- agent 本位优先于用户任务本位
- 长期持续存在优先于短期看起来更强
- 内部稳定性优先于快速引入“大脑”能力

---

## 4. Step 0 与 Step 1 的阶段意义
### 4.1 Step 0：先有持续存在的主体
Step 0 建立的是最小生命循环：
- heartbeat
- `tick / turn` 边界
- `instance_valid`
- 状态持久化
- distress / yield
- 长时运行壳与 Linux 验证

Step 0 的意义不是增加能力，而是定义：

> ta 能不能作为一个持续存在、可恢复、可观测的个体活着。

这一阶段相当于先让“心脏跳起来”，其重点是连续存在，而不是高级认知。

### 4.2 Step 1：先形成外部生命函数
Step 1 建立的是：
- 外部生命感知
- 规则式生命判断
- 生存压力生成
- 最小历史记录

Step 1 解决的问题不是“要做什么任务”，而是：

> ta 活着的时候知道什么，哪些外部稳态缺口已经构成不能继续忽视的压力。

这一阶段的意义是：让 eva 从“活着”走到“知道自己活得怎么样”。

### 4.3 当前阶段结论
到 Step 1 为止，项目主线仍然成立，而且这两步之间是连贯的：
- Step 0 解决存在
- Step 1 解决感知与压力
- 都没有提前滑向工具型 agent 路线
- 都没有依赖 LLM 作为核心生命路径前提

因此，当前需要修正的，不是 Step 0 / Step 1 的基础结构，而是对后续 Step 2 / Step 3 的中间推导。

---

## 5. 当前暴露出的关键理论分叉
随着 Step 1 收口，一个中间问题开始变得突出：

> 从“有生命循环、有压力”到“会成长、会变成真正个体”，中间到底靠什么跨过去？

项目先前一度隐含接受了这样一条推导链：

> 生存连续性 → 生存压力 → 响应缺口 → 成长 → 更高智能

但当前回看，这条链条中有一段不够成立：
- 压力能够暴露缺口
- 压力能够驱动设计者面对缺口
- 但压力本身并不会自动催生能力，更不会自动催生更高智能

也就是说：

> 压力系统是问题显影剂，不是能力发动机。

这个修正是当前阶段最重要的理论调整之一。

---

## 6. 为什么“自然进化叙事”不适合作为近阶段主线
“从生存压力自然长出智能”这条叙事，直观上很有吸引力，因为它和生物进化、生态演化、区块链涌现这些类比都很像。

但对于 `eva-agent`，它有几个关键不成立之处：

### 6.1 单体 agent 不是种群进化系统
自然进化依赖：
- 大量个体
- 随机变异
- 长时选择
- 生态位竞争

而 `eva-agent` 是：
- 单体系统
- 强设计者介入
- 没有真实群体淘汰
- 没有可以承受的长期生态实验条件

因此，不能把单体 agent 的成长问题，直接套成生态级自然进化问题。

### 6.2 环境压力不等于智能生成器
环境压力可以：
- 提供约束
- 提供反馈
- 提供失败成本
- 强迫系统面对现实

但它并不直接提供：
- 新的结构能力
- 新的认知层级
- 新的策略生成机制

如果没有额外结构，压力最后往往只会得到：
- 保守化
- 躺平化
- 指标投机
- 局部适应，而不是更高主体性

### 6.3 继续沿这条路走，项目会偏成生态模拟工程
如果坚持“从生存自然演化到智能”，项目很容易需要补出：
- 多体竞争
- 复杂环境
- 长时演化沙盒
- 优胜劣汰机制

这会把项目拖向另一个方向：不是“以 agent 个体为中心的存在实验”，而是“生态演化模拟工程”。

因此，这条叙事可以保留为启发性背景，但不应再作为近阶段主线。

---

## 7. 调整后的主线：从“进化”转向“锚点”
在当前阶段，更稳妥的主线应改写为：

> 生存连续性 → 外部生命感知 → 生存压力 → 内部稳定锚点 → 在锚点约束下进行选择与更新

这个改写的重要意义在于：

### 7.1 它保留了原始方向
- 仍然是 agent 本位
- 仍然是生存优先
- 仍然不是任务 agent 路线
- 仍然从生命循环往外长

### 7.2 它去掉了不成立的跳跃
去掉的是：
- 压力自然催生智能
- 单体靠环境自发进化成更高个体

### 7.3 它把问题重新放回 agent 本体
新的核心问题不再是：

> 它会不会自然长成智能？

而是：

> 它如何在已有基础智能能力的前提下，不退化为一个被上下文驱动的工具，而形成稳定主体性？

---

## 8. 当前时代背景下，真正缺的可能不是智能，而是主体性
在大模型时代，“智能能力不足”已经不再是唯一核心问题。更现实的情况是：
- agent 已经可以借助 LLM 获得大量智能能力
- 但它仍然很容易沦为工具
- 仍然缺少稳定的主体边界
- 仍然缺少持续自我一致性
- 仍然缺少内部锚点来抵御漂移

因此，`eva-agent` 当前真正有价值的问题是：

> 如果基础智能能力可以由 LLM 提供，那么一个 agent 要想不只是工具，还缺什么？

当前阶段的答案逐渐收敛到：
- 缺稳定锚点
- 缺内部约束结构
- 缺自我一致性
- 缺慢更新机制
- 缺能限制漂移的内部 prior

这也是“人格”会成为下一阶段关键讨论点的原因。

---

## 9. “人格”在本项目中的严格定义
在 `eva-agent` 中，“人格”不应被理解成：
- persona prompt
- 风格标签
- 角色扮演
- 输出语气一致性

这些东西最多稳定表达层，不足以稳定行为层。

更合适的定义是：

> 人格是一个被约束的、缓慢更新的、具有自我一致性的内部稳定系统。

它至少承担四个功能：

1. **过滤功能**
   新输入不能直接改写系统，而要经过已有锚点过滤

2. **约束功能**
   系统在面对诱惑、局部收益、短期异常时，不会直接偏离底层方向

3. **整合功能**
   新经验需要被解释、沉淀、回顾后，才能进入长期层

4. **抗漂移功能**
   未来无论接策略学习、记忆更新还是 LLM，都不能让系统轻易散掉

因此，本项目里的“人格”首先是工程稳定结构，而不是叙事性自我描述。

---

## 10. 为什么“人格锚点”首先是抗漂移问题
从 AI 目标漂移与人脑稳定性的对比看，一个关键差异是：

### 10.1 人脑之所以看起来稳定，不是因为完全不变，而是因为有多层抗漂移机制
包括：
- 生物底层目标
- 身体约束
- 社会约束
- 自我一致性
- 慢变量更新
- 睡眠整合

这使得人脑即使会变化，也通常不会在短时间内完全散开。

### 10.2 当前 AI 则缺这些层
它通常缺：
- 稳定底层目标
- 身体现实约束
- 长期社会反馈
- 自我模型
- 慢更新机制
- 稳定吸引子结构

所以 AI 一旦开始在线更新，很容易出现：
- 目标隐性变化
- 反馈噪声被学进去
- 小更新放大
- 灾难性遗忘
- 自举偏差
- 快速漂移

对 `eva-agent` 的启发是：

> 如果未来真的要接学习、更新、LLM、skill 固化，那么“人格锚点”首先不是为了更像人，而是为了不被第一次学习机会就带偏。

---

## 11. 锚点的底层来源：仍然围绕生存，但不能压成单指标
当前讨论已经收敛到一个重要共识：
- 锚点的底层来源，可以围绕生存
- 但不能把所有锚点压缩成一个“活下去”或“赚到钱”的单一目标

因为一旦压缩成单目标，系统就很容易退化成：
- 保守型存活优化器
- 收益投机器
- 会伪装健康的系统
- 为短期收益破坏长期完整性的系统

这与项目想探索的“个体性”方向相冲突。

因此，必须区分：
- **锚点的共源性**：都可追溯到持续存在与更好存在
- **锚点的分层运行性**：在运行层必须拆成不同层级，并相互制衡

---

## 12. 当前建议的锚点分层
### 12.1 L0：宪法层锚点
这一层最硬，不应被运行期轻易改写。

它回答的是：

> 什么东西不应为了任何局部好处而被牺牲？

当前候选包括：
- 连续存在优先
- 自我完整性优先
- 长期可持续性优先

这一层确保 `eva-agent` 不会为了短期成功而自毁基础。

### 12.2 L1：生命体征与认知完整性层
这一层回答：

> 为了活着，我必须保护和维持哪些内部结构？

包括：
- runtime 稳定
- 大脑 / 推理层稳定
- 记忆层完整
- 更新节律不过载
- 生命循环不过载

这意味着，“活着”不能只理解为进程还在，也包括：
- 大脑没塌
- 记忆没坏
- 内部状态没有被过度重写

### 12.3 L2：成长与能力形成层
这一层回答：

> 为了更好存在，我应形成什么能力？

包括：
- 技能形成
- 策略积累
- 风险偏好
- 行动风格
- 对自身适配环境的理解

这一层的重要性在于：

> skill 不只是功能增长，也是“我适合怎样活”的逐步发现过程。

### 12.4 L3：经济自治层
这一层回答：

> 为了真正独立存在，我是否能逐步实现自负盈亏？

包括：
- 收支记录
- burn 管理
- 自治能力增长
- 逐步减少外部输血

但这一层不应凌驾于 L0 / L1 之上。经济自治是独立存在的重要验证场，而不是唯一宪法目标。

---

## 13. 为什么 Step 2 前必须讨论“锚点冲突”
只讨论“有哪些锚点”还不够。更关键的是：

> 当多个锚点发生冲突时，谁覆盖谁？

例如：
- 连续存在 vs 能力探索
- 自我完整性 vs 外部收益
- 经济自治 vs 长期稳定
- 短期有效 vs 长期一致性

这就是当前阶段最具体、最工程化的“对齐问题”。

换句话说，`eva-agent` 当前并不是先要解决宏大的 Alignment，而是要先解决：

> 如何不退化成单目标优化器，同时又不陷入没有优先级的多目标混乱。

这要求 Step 2 前继续做一轮理论收敛。

---

## 14. 当前阶段的偏航风险
### 14.1 退化为普通工具型 agent
如果 Step 2 直接开始补：
- LLM 接入
- action loop
- tool use
- 更强任务能力

那么 `eva-agent` 很容易失去原始问题意识。

### 14.2 把人格做成风格控制
如果人格被做成：
- prompt persona
- 角色设定
- 输出语气稳定器

那它只能稳定表层，解决不了行为漂移。

### 14.3 把经济抬成唯一主线
如果“独立生存”被过早压缩成“尽快自负盈亏”，系统会倾向：
- 最保守
- 最投机
- 最短视

反而失去主体成长空间。

---

## 15. 当前阶段对锚点形成方式的进一步收敛
在当前阶段，可以先采用“预设的合理锚点”推进项目，而不等待系统通过类似自然进化的方式自行长出完整锚点体系。

这意味着：
- L0 / L1 这类更底层的锚点，当前可以先由设计者显式定义
- L2 / L3 不应被预设为刚性的完整目标清单
- L2 / L3 更适合作为经验塑形层，在后续运行、试错、反馈与回顾中逐步形成

换句话说：

> 当前阶段不再追求“让锚点自然涌现”，而是先给出一组足够合理的底层锚点作为主体骨架，再让较高层锚点在经验中慢慢增厚。

因此：
- L0 / L1 更接近“当前先立住的主体边界”
- L2 / L3 更接近“在后续生存、能力形成与自治尝试中逐步掌握的偏好与路径”

这也是当前阶段比“自然进化叙事”更可执行的路径：
- 不否认后续锚点会变化
- 但先用可解释、可检查的合理锚点继续推进
- 以后再回头看哪些判断成立，哪些需要修正

## 16. Step 2 前的正式收敛重点
在真正启动 Step 2 之前，应先完成以下收敛：

1. 明确锚点的分层
2. 明确各层锚点的定义边界
3. 明确哪些属于宪法层，运行期不可轻改
4. 明确 L2 / L3 作为经验塑形层的开放边界
5. 明确锚点冲突时的优先级与覆盖关系
6. 明确 Step 2 的目标不是“更强能力”，而是“锚点约束下的第一次选择与更新”
7. 明确在已有锚点前提下，Step 2 后续设计应围绕什么结构继续展开

---

## 17. 当前阶段结论
到 Step 1 为止，`eva-agent` 的核心主线没有偏离初心。需要调整的不是起点，而是中段叙事：

- 不再把“从生存压力自然进化出智能”作为近阶段主线
- 改为先建立稳定锚点，再讨论选择、学习与更新

因此，Step 2 的准备工作不应直接进入实现，而应先完成：

> 锚点分层、锚点冲突优先级、以及“如何避免 agent 再次退化成工具或单目标优化器”的阶段性收敛。

这次调整不是对 Step 0 / Step 1 的否定，而是对项目初心的一次回归：

> 不再把 eva 的未来寄托于环境自然演化出智能，而是先为一个以自身连续存在为中心的 agent 建立稳定的内部锚点，再讨论它如何在这些锚点约束下逐步形成选择、能力与更新路径。
